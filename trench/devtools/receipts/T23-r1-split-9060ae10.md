### Problem
`r1_cases` loaded all 128 of the #866 R1 pages inside one test, so it held the GPU test guard for the whole run. Alone at load 13 it held the guard **150.4 s**, past the guard's 120 s `MAX_WAIT`. ### Change
- **Hold-time check.** `within_half_the_gpu_guard` makes a part fail when it holds the guard for half of `MAX_WAIT` (60 s) or more, and it names the part. The clock starts once the guard is taken (`test_gpu::hold_for_this_test()` is idempotent), so time spent queued behind other tests is not counted.
- **Split.** The cases now run as `r1_part_00..15`, 16 tests of 8 cases each. Case `i` goes to part `i % 16`. Round-robin matters: with contiguous chunks the three 300-node loops (cases 112–114) all landed in one part, which held the guard 24.7 s at load 8 and failed the 60 s check in a full run at load 18–24.
- **Pins that need no engine.** `r1_parts_cover_every_case_once` fails if the JSON grows past 16×8 cases or would leave a part empty. `r1_part_list_matches_r1_parts` checks that the test list matches `R1_PARTS`.
