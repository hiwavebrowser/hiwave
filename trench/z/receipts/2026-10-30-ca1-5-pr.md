## CA1-5: console_log's label map is per test thread (the develop flake)

Castor's A1 audit, item 5 (PLAN-z row CA1). `console_log` keeps the labels a log line names (`inline#N`, `script#N`, `inserted#N`) in one process-wide map, and looks a label up newest first. Under parallel test threads, two tests that both record `inserted#1` read each other's URL. That is why `console_log::tests::script_places_inserted_scripts_and_imports_drop_the_query_too` failed on develop under load (3c6b170e, #828's run) and passed run alone.

### Fix
Port of hiwave-linux `12464a45` (Castor): one access point, `with_aliases`.
- In the shipped build it is still the one shared map (`#[cfg(not(test))]` on the `OnceLock` static). Behaviour is unchanged.
- In test builds each thread has its own map (`#[cfg(test)]` thread-local `TEST_ALIASES`), and `force_for_test` empties it, so every test starts with no labels.

Every `alias()` call is on the page thread, the same thread that resolves the labels: engine lib.rs (inline and external scripts) and script_net.rs (inserted scripts). Net-runtime lines (`net()`) resolve no labels, so a per-thread map loses nothing.
