## RD3: a box with a keyframe animation paints the frame it settles on

PLAN-z row RD3, pick (b) from Atlas's 10-30 04:25 note. The engine parses `@keyframes` and runs no animations. `group_opacity` painted **any** box naming an animation at opacity 1, so that `opacity: 0; animation: fadeIn 1s forwards` would not stay invisible. That is why reddit's interstitial disc (`opacity: .75`, an infinite animation) painted solid.

### Fix
- **Parser:** `@keyframes` and `@-webkit-keyframes` now carry a name and the `opacity` at 0% and 100% (`from`/`to`, percentages, selector lists). Nothing else of the rule is kept; there is no timer and no ticking.
- **Cascade:** element and pseudo-element styles resolve `animation_settled_opacity` once:

| Animation | Frame painted |
|---|---|
| Finite, `forwards`/`both` | the keyframe it ends on (direction and count decide which end) |
| Finite, no forward fill | the box's own `opacity` |
| Infinite | its first keyframe if that sets `opacity`, otherwise the box's own |
| An end that sets no `opacity` | the box's own |

- **Layout:** `group_opacity` reads that value, and falls back to today's 1 when there is none.
- **Shorthand:** `animation` now replaces an earlier `animation` whole (a stale `forwards` used to survive) and reads a numeric iteration count (`d 1s 2 alternate forwards`). The count used to go to the timing function.

### Where this differs from the 04:25 note, for the reviewer
1. **A finite animation without a forward fill settles on the box's own value, not the 0% frame.** The note reads "otherwise the box's own opacity unless the 0% frame sets one". Applied to a finite animation, `.page { animation: fadeIn .5s }` with `from { opacity: 0 }` would be invisible for good. The 0% rule therefore applies only to infinite animations, which never settle. This is the frame a real engine ends on, and Chrome agrees (table below).
2. **The note's shape `opacity:.75; animation: x 1s forwards` is not reddit's rule.** Reddit's is `infinite`, with `opacity: 0` at 100%. Both are tested: the forwards shape paints the 100% value, reddit's paints `.75`.
3. **What cannot be settled stays at 1, where Chrome uses the box's own value:** no `@keyframes` of that name, several animations in one value, or an end value it cannot read (`var()`). A rule we failed to carry must not hide a page. An `@keyframes` inside `@media` is carried whatever the query says.

### Known gaps
- **An infinite animation whose first frame is `opacity: 0` now paints invisible.** A blink or pulse from 0 is gone in the static frame, where it painted at 1 before. That is the literal t=0 frame and the chosen rule. The 20-site A/B shows no such case, but it is the most likely place for a hand-test report.
- `getComputedStyle().opacity` still returns the box's own value, not the settled one.
- A fractional iteration count takes the end frame; Chrome would hold a midpoint.
