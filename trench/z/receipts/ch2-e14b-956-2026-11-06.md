**CH2.E14b** (PLAN-z.md, from #937's review): an element's `var()` with no value and no fallback must compute to `unset` (CSS Variables 1 §3). #937 did this for `::before`/`::after`; the element cascade still kept the earlier declaration.

## What changes
- **Element rule cascade and inline `style=`** now substitute with `resolve_css_variables_or_invalid`, the helper the pseudo-element cascade uses since #937. When substitution fails, `apply_invalid_at_computed_value_time` applies `unset`: the parent's value for an inherited property, the initial value otherwise. The declaration still wins the cascade, so `width:50px; width:var(--missing)` is `auto`, not 50px.
- Inline `--*` declarations are skipped in the value pass. They are already in the element's custom-property set (first pass), and `style.custom_properties = vars` overwrites the style's set afterwards.
- **`apply_initial_value`**, which the fix now reaches, had two errors of its own:
  - The initial `display` was `block`; Chrome's is `inline`. So `div{display:unset}` stayed a block.
  - The `margin`, `padding` and `border-width` shorthands reset only their top side.
