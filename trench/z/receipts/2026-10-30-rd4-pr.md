## RD4: a `url()` paint that names no server paints its fallback colour

This is PLAN-z row RD4, from the lane's RD1 reduction of reddit's interstitial. SVG 2 §13.2: with `fill: url(#missing) #ff4500`, the reference names nothing, so the shape paints `#ff4500`. `Paint::parse` (rustkit-svg) kept only what was inside `url(...)` and dropped the fallback, so the shape painted nothing (white on the probe page).

### Fix
- `Paint::Url(id)` becomes `Paint::Url(id, fallback)`.
  - The fallback is the `none`, `currentColor` or colour after the closing paren.
  - Anything else after the paren leaves no fallback (unchanged: paints nothing).
- `Paint::resolve` returns the fallback for a `url()` that is still unresolved at paint time. That covers both the document with no paint servers at all and a reference the resolve pass could not find.
- A `url()` that names a gradient still becomes `Paint::Gradient`, exactly as before.
- Neighbouring behaviour: a **stroke** `url()` is never resolved to a gradient (stroke gradients aren't painted), so `stroke: url(#grad) red` now paints red where it painted nothing. Chrome paints the gradient there; the colour is the nearer of the two. Without a fallback, a stroke `url()` still paints nothing.
