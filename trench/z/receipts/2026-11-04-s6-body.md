## S6: a stylesheet that misses the load's budget applies when it arrives

PLAN-z row **S6** (Iris real-window top-20 on 6ef43673): microsoft's 37 external sheets only finished near the end of a ~54 s run and the page stayed mostly unstyled: "sheets that arrive late never trigger a restyle".

**Cause:** `load_external_stylesheets` raced every sheet against `subresource_budget_ms` (8 s) and **dropped** one still loading at the deadline ("rendering without it"). With 6 sheets at a time, 37 sheets queue into that deadline. Nothing fetched them again, so the page never got them. Chromium never drops a stylesheet; it applies it when it arrives.

**Fix (engine only):**
- Each sheet's fetch is now a future that owns its loader, inspector and request (`fetch_stylesheet`). At the deadline the load still ends (the budget is unchanged, so the load does not wait longer), but a sheet still out **keeps its fetch**, the same request rather than a second one, in `view.live_sheets`.
- `pump_live` settles them. Each arrival is inserted at its document-order slot (`view.external_sheet_slots`), so a later sheet still wins the cascade. `data:` web fonts in it are loaded, and the page is restyled (`RelayoutCause::StylesheetLoaded`). Late sheets count in `LivePump::in_flight`, so the loop keeps turning while they are out.
- A new document clears both (`reset_for_new_document`).

**Red first:** `054b2019` `page_script_tests::a_sheet_that_misses_the_budget_applies_when_it_arrives`. Budget 500 ms; `/slow.css` (answers after 3 s, `#box{width:123px;color:red}`) is linked before `/fast.css` (`#box{color:blue}`). The load must end under 2.5 s without it. Live turns must then apply it: width 123, and the color must stay blue (document order). **On develop 76c6ff8b the width is still 384 after 10 s of live turns.
