## GCS1: `getComputedStyle(el, pseudo)` reads the pseudo-element

This is PLAN-z row GCS1, found during the #821 R1. The second argument was ignored, so the Bootstrap-era breakpoint idiom `getComputedStyle(body, "::before").content` read the host element's row.

### Fix
- **Build:** `ViewLayout::pseudo_styles` keeps each element's cascaded `::before`/`::after` style. It is recorded before the box step because a `display: none` pseudo has no box, and that is the usual shape of the idiom. A full build clears the map; a restyle replaces or drops what it walks.
- **Snapshot:** the lazy geometry source adds the rows to the element's lines, named `::before <property>`. Nothing is formatted until a script reads.
- **Script:**
  - `::before`, `:before`, `before` and any case of them name the pseudo.
  - `undefined`, `null` and `''` read the element.
  - `::first-line` and `::first-letter` read the initial and inherited values, with `content: normal`.
  - An unknown name reads an empty style.
  - With no rule, `content` reads `none` and `display` reads `inline`, plus the inherited values.
  - `::marker`, `::selection`, `::backdrop` and `::placeholder` take the same path as `::first-line`. No test or probe covers them.
- **The row's second half:** a `content` value holding a function or a quote keyword (`attr()`, `counter()`, `url()`, `open-quote`) now resets a string from a lower-precedence rule. An invalid value such as `5px` is still dropped.

### Behaviour change on paint
A pseudo with `content: "lower"` overridden by `content: attr(x)` used to paint `lower`. It now paints nothing. Chromium paints the attribute's value, and the engine does not generate it yet.

### Known gaps
- A pseudo with no `content` string (`content: none`, or a rule with no `content`) reads only what it inherits, because the cascade keeps no style for it. Chromium reads the rule's values, for example `color`. A test pins this for `content: none`.
- `attr()`, `counter()` and `url()` read `none`. Chromium reads `"val"`, `counter(c)` and `url("...")`.
- `width` and `height` read the declared px length or `auto`, not used values. Margins, padding and border widths read 0.

### Found, not fixed
An empty `<div>` reads `display: none` from `getComputedStyle` on develop; Chromium reads `block`. The new tests give their divs text so that this stays out of the PR.
