## C2(c): `scrollIntoView` and fragments move every enclosing scroller

PLAN-z row C2, slice (c). Off develop `546d6196`.

Before this, `scrollIntoView` only moved the window, so a target inside a scrolling box stayed out of sight. Fragment navigation moved the window's y and nothing else. Setting `location.hash` did nothing at all.

### Rule, from Chromium 143.0.7499.4 on the same pages
- Each scroller around the element in turn, innermost first, then the window. `block` and `inline` apply at every level.
- `overflow: hidden` is moved; `overflow: clip` is not a scroller.
- An absolute box skips a scroller its containing block is above. Nothing moves a fixed box except the scrollers inside it, and the window stays put. An element with no box scrolls nothing.
- `nearest` follows CSSOM View for a target taller than the scrollport: when it already covers the scrollport, nothing moves.
- Fragments: the same scroll with `start`/`nearest`, before `hashchange`. It finds an id, then `<a name>`, as written and then percent-decoded. `top` (any case) and the empty fragment go to the top of the window only; no match stays put. `pushState` does not scroll. The same link clicked again scrolls again, with no new history entry.

### How
- `info(el, 'scrollChain')` reports the scrollers from the geometry snapshot and whether the window moves. `intoView` in `web_scroll.js` is the one path.
- All fragment routes (link click, `location.href`, `replace`, `assign`, `location.hash`) go through `__rustkit_fragment_navigation`. `Engine::navigate_to_fragment` no longer does its own scroll math.
- A page loaded with a fragment opens there at the end of the load, unless the window has already moved.

### Changes beyond the row's wording
- **`location.hash` is now a working setter.** It was a plain data property. Pages that assign it now navigate and hear `hashchange`, which they did not before.
- **Two extent residuals from the (a) R1 are fixed**, because scroll clamps depend on them: a scroller counts its padding at the end, and clipped content is no longer overflow of a scroller around it (`overflow: clip` too). The absolute boxes that escape the clip still count. This moves `scrollHeight`/`scrollWidth` on those boxes. Script and paint use the same number.
- **An existing test changed:** `a_fragment_jump_is_a_scroll_the_page_sees` now pumps before reading. A fragment's `scroll` event comes from a timer, like any scroll script asks for, where it used to fire inside the click. The test now pins exactly one event.

### Known gaps
- **No real-window run.** This seat has no input grant; the plan gives the check to Atlas's seat. Worth trying: a link click into a nested scroller, and opening a URL with a fragment.
- **The window has no horizontal extent** (`max_scroll_offset.0` is always 0, before and after this PR). Where Chromium also moves the window across, these tests expect x to stay 0: 12, 170 and 400 in Chromium, listed in a comment in the test file. The scrollers' own x is Chromium's.
- `scroll-margin` and `scroll-padding` are not parsed. Chromium honours both here, so a page with a sticky header lands under it.
- In-flow `margin-bottom` in a scroller's extent: Chromium 109, engine 100 (`c2c_extent_probe.mjs`).
- A fixed box held by a transform still counts as fixed for the window. A fixed ancestor across a shadow boundary is not seen. Neither is tested.
- `getBoundingClientRect` ignores transforms (C10), so a transformed target lands off by the transform. Chromium: 1768 on the probe page; not tested here.
- A late layout does not re-apply a load's fragment scroll, as Chromium's anchor does until the user scrolls.
- Back and forward within a document do not scroll; not touched.

### Found, not fixed
**An absolute box with no positioned ancestor is placed from its static parent, not the initial containing block.** On untouched develop `546d6196`, `top:300px` under a static parent at y=200 paints at rows 500-519. In Chromium 143 the same shape with `top:1800px` under a parent at y=1000 reads 1800, where the engine reads 2800. It happens with plain, `auto` and `hidden` parents. The cause in layout is not traced. The engine test for skipping a static scroller keeps the scroller at y=0 to stay clear of this.
