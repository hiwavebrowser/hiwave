## What

Lit adopts constructed stylesheets (`adoptedStyleSheets`) and never injects a `<style>`, so a Lit component's `:host` display and its shadow tree's rules never reached the cascade. Lit's template markers `<?lit$…$>` also lost their `?` in the tokenizer, so Lit could not find its parts (named slots were not cloned).

- **web_cssom.js**: Document and ShadowRoot share one `adoptedStyleSheets` implementation (it replaces web_shadow.js's recording placeholder on ShadowRoot). Setting the list publishes each adopter's CSS text through `__rkSetAdoptedStyles`. So does a later edit of an adopted sheet (`replaceSync`, `insertRule`, `deleteRule`, declaration edits). A disabled sheet publishes as an empty string.
- **rustkit-bindings dom.rs**: `__rustkit_dom_set_adopted` stores the texts on the node and marks style dirty. **rustkit-dom**: `Node::adopted_styles`, which node replacement carries over.
- **Cascade**: a shadow tree's adopted sheets follow its `<style>` elements (`shadow_tree.rs`). The document's adopted sheets follow its `<style>`/`<link>` sheets (`build_layout_for_view`).
- **New in the re-cut, not in e1d795a4**: the rule index's fingerprint vouches only for the `<style>`/`<link>` sheets. A build whose document has adopted sheets now gets no fingerprint, so the index compares selectors instead. Before, a fingerprint match reused an index that had never indexed the adopted rules: the document test stayed red with e1d795a4's change alone (`#d` 800 wide instead of 123). This is the #758 seam the lane noted on 10-21.
- **Tokenizer**: `<?` starts a bogus comment whose data keeps the `?` (HTML: unexpected-question-mark-instead-of-tag-name, reconsume in the bogus comment state).
