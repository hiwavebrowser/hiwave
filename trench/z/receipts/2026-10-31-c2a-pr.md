## C2(a): an overflow box scrolls

PLAN-z row C2, slice (a). `scrollTop`/`scrollLeft` on an `overflow: auto|scroll|hidden` box were stored and clamped, and nothing read them: children stayed put in paint, in rects and in the hit test. Now all three follow, as in Chromium 143.0.7499.4.

### How
- **One table per view** (`ViewLayout::element_scrolls`), shared with the bindings. Script writes it and reads it back at once; a new document clears it.
- **Layout is untouched.** A scroll rebuilds the display list over the same boxes (`relist_after_element_scroll`). A relayout copies the offsets onto the new boxes and clamps them (`stamp_element_scrolls`). A page where script scrolled no element pays for neither.
- **Paint:** a translate just inside the box's clip. It is escaped together with that clip, so an absolute box whose containing block is above a static scroller stays put. A fixed box undoes any translate left open by a positioned scroller.
- **Hit test:** the box adds its scroll for its children, with the same out-of-flow rule.
- **Rects:** `geometry_snapshot` stays unscrolled and each box names the scroller that moves it. A read adds up the chain, so a scroll does not cost a new snapshot. `offsetTop`/`offsetLeft` read the unscrolled position, as Chromium does.

### Behaviour changes beyond the row's wording
- An element now gets its own `scroll` event: one per task, from a timer, not bubbling. Nothing fired before, so a page's scroll handler on a box now runs.
- `overflow: visible`, `overflow: clip` and `body` keep `scrollTop` 0. `visible` used to store the write.
- A box's own border no longer counts as scrollable overflow. A bordered box read a `scrollHeight` too large by its border, which also let it scroll past its end. This moves `scrollWidth`/`scrollHeight` for every bordered element.
- Writes round to a whole pixel (30.5 reads 31, 30.4 reads 30, as in Chromium).
- The diagnostics note now appears only when the container is actually scrolled, and says the position is from before the scroll. Diagnostics positions still ignore element scroll.

### Known gaps
- The wheel and trackpad still scroll only the window: that is slice (b). `scrollIntoView` and fragment navigation still scroll only the window: slice (c). Sticky inside a scroller: slice (d).
- `body` under an `html` that clips is a scroller in Chromium and takes no offset here.
- A fixed box inside a **positioned** scroller is not moved by the scroll, but it is still clipped by that box. The clip is not new. Rects are right; there is no pixel pin for it.
- An absolute or fixed box that escapes a scroller still counts toward that scroller's `scrollWidth`/`scrollHeight`, and its hit test is still pruned by the boxes above it. Both are old.
- Other readers of box coordinates do not apply the offset: text selection rects, and `Range` rects if they read boxes directly. Not tested.
- A real-window check has not been run; the plan gives that to Atlas's seat.

### Found, not fixed
A `position: fixed` box inside a box with a relative offset moves with that box (#843's `shift_subtree`): `top: 10px` on the parent reads the fixed child at y 10 where Chromium reads 0. The fixture uses a margin to stay out of it; this goes on C12.
