**What was wrong (develop 6090c1eb vs Chromium 143.0.7499.4):** an `<img>` grid item was given its whole area across and a row of 0, so card grids lost every picture: a 40x20 image in a one-column grid read 400x0 (Chromium 40x20), `width: 100%` in a 200px column 400x0 (Chromium 200x100). A `width: 100%` image inside a grid item's wrapper was sized against the grid container: 400x200 in a 200px column.

**Red:** `5466ec03`, `crates/rustkit-engine/src/replaced_ratio_tests.rs`, 33 hand-made bodies, Chromium rows from `trench/z/tools/c10/replaced_ratio_probe.mjs` (generator `replaced_ratio_gen.py`). 27 of 33 wrong on develop.

**Fix:** `f79319a5` (rustkit-layout `grid.rs` only):
1. `place_item_in_area` gives an `<img>`/inline `<svg>` item the replaced-element sizing in a containing block the size of its area (css-grid-1 §6.2) and aligns it: `normal` is `start` for a replaced box in both axes (css-align-3 §6.1/§6.2). The engine has no `normal`, so the default `stretch` is read as `normal` for these items; an image a page stretches on purpose keeps its size (a known cost, said here).
2. Phase 9 records the image's height as its real height, so Phase 9.5 no longer shrinks the row to an empty item's 0.
3. Row contribution: the used height at the width the item's columns give it.
4. Column contribution and the min-content estimator: a replaced box with a percentage `width` or `max-width` is compressible (css-sizing-3 §5.2.2), min-content contribution 0 plus a length `min-width`.
5. Phase 9's block arm re-runs the replaced sizing for an image grandchild whose `width`/`max-width` is a percentage, against the item's width (the pre-pass used the container's). Other images keep their pre-pass size as before.

**After:** 0 of the 24 in-scope rows wrong: every `<img>` grid row and both card patterns (a `<div>` in a `1fr` column holding a `width:100%` image, with and without `aspect-ratio: 16/9; object-fit: cover`) match Chromium. 13 rows moved to the skip list (below).
