## SV1: parsed SVG elements take the SVG namespace and their real names

This is PLAN-z row SV1, from the Y2 reduce. The tokenizer lowercases every name and the parser's sink put every element in the HTML namespace. So a script reading a parsed `<svg>` saw `tagName` `SVG`, `getAttribute('viewBox')` null and `instanceof HTMLElement` true. Chrome keeps `svg`, `viewBox` and `SVGSVGElement`.

### Fix
- **Parser (`rustkit-dom`, new `svg_names.rs`):** the sink applies HTML §13.2.6.5.
  - `<svg>` and everything under it is in the SVG namespace.
  - `foreignObject`, `desc` and `title` hold HTML. Breakout tags stay HTML, and `font` breaks out only with `color`, `face` or `size`.
  - Element and attribute names come from the spec's tables.
  - The tree builder's open-element stack stays lowercase, so end-tag matching does not change.
- **Fragments:** `innerHTML` on an SVG element parses as SVG. `insertAdjacentHTML` does too, because its holder is now made in the SVG namespace.
- **`SVGElement`:** gains `dataset`, `tabIndex`, `nonce` and `autofocus`, which it shares with HTML elements (`HTMLOrSVGElement`). Parsed SVG elements had these only because they were wrongly HTML.

### Behaviour changes on parsed SVG, all as Chromium 143 answers on the probe
- HTML-only members are gone: `click`, `innerText`, `offsetWidth`, `hidden` and `title` read `undefined`.
- `getAttribute('viewbox')` is null, and `setAttribute` keeps the case it is given.
- A CSS `[viewbox]` no longer matches a parsed `<svg>`, and `[viewBox]` now does. This is from reading the matcher, which compares the name as written; no test pins it.
- A `<template>` under `<svg>` is now a plain element with no `content`, as the spec says. This is from reading the code; no test pins it.

### Known gaps, unchanged by this PR
- A breakout tag gets the right namespace but stays inside the `<svg>`. Chromium moves it out.
- `<svg><title>` is still tokenized as RCDATA, so `<title><b>` holds text. Chromium builds a `<b>`.
- MathML is still parsed into the HTML namespace with no name adjustment (`definitionURL`).
- `Range.createContextualFragment` still parses in an HTML context.
- `className` on an SVG element is still a string; Chromium has an `SVGAnimatedString`.
- `getElementsByTagName` and type selectors stay case-insensitive on SVG names, so they can over-match.
