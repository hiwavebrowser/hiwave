## S1: a redirected navigation commits the last hop's URL (gmail unstyled)

PLAN-z row **S1** (Pete's hand test 11-03): every stylesheet at `www.gmail.com/assets/*.css` 404s, so gmail is unstyled.

**Cause** (lead from the row, confirmed by the Grok measurement on develop 13f505d7 and here): `www.gmail.com` 301 → `mail.google.com/mail/u/0/` 302 → `accounts.google.com/...`. The loader follows the hops, but `load_url_for_nav` kept using the **requested** URL after the fetch: `view.url`, the commit event (address bar), `location`, `document.baseURI`, the history entry, and so the base for every relative stylesheet, script and image. So the sign-in page's relative assets were asked of `www.gmail.com`. This is general: any site that redirects across hosts or paths (http→https+www, `/` → `/en/`, login bounces) resolved its relative URLs against the wrong place.

**Fix:**
- engine `load_url_for_nav`: after the fetch, if the response came through redirects, `url` is rebound to `response.url` (keeping the request's fragment when the last hop has none, per Fetch); everything after it (commit event, `view.url`, `document-replace`/`navigation-commit` log lines, inspector commit, scripts, subresources, `PageLoaded`) uses it.
- `rustkit-core`: `NavigationStateMachine::redirected_to(url)` puts the last hop on the provisional navigation, so the history entry and `DidCommitLoad` carry it (Back/reload go to the final page, as Chromium).
- The inspector pin `a_redirect_chain_is_recorded_between_the_request_and_its_response` now expects `navigation_commit /final 200` (it pinned the old behaviour).
