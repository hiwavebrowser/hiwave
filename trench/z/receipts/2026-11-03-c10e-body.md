**Fix** `4b65266b` (`rustkit-layout/src/flex.rs`): for a non-replaced flex item with a preferred aspect-ratio:
1. a base size that comes from content goes through the ratio from a definite cross size (the explicit one, or the stretched width of a column with a definite width): an empty `aspect-ratio: 4/1` item in a 400px column was 0 tall, Chromium 100; `height:50px; aspect-ratio:2/1` in a row was 0 wide, Chromium 100;
2. in a row, the height comes from the used (flexed) width, not from the width the block pre-pass used: `flex: 0 0 120px; aspect-ratio: 2/1` was 120x200, Chromium 120x60; two `flex:1; aspect-ratio:1` were 200x400, Chromium 200x200;
3. in a column, an unstretched item with a definite height gets its width through the ratio (was fit-content).

**10 of the 21 red rows now match.** Not fixed, left out of the test and listed in its module doc (they were wrong on develop too):
- replaced boxes (natural ratio) in flex and grid: an img in a flex column keeps its natural height (100x20, Chromium 100x50); an img or canvas that is a grid item is 0 tall, and `width:100%` reads the grid container, not its column (400x0, Chromium 200x100); `flex:1` img keeps natural height; canvas in a flex row is 0 tall;
- block flow: a float with `height` + `aspect-ratio` and auto width is 0 wide (Chromium 100).
