## What

By default, the app's info log carried whole page URLs, query and fragment included. Those lines were: `Navigating content to`, `Deferring restored-tab navigation`, `Link clicked`, `Form submitted`, `Script navigation`, `New window request …`, `Content navigating to`, the tab-switch lines, iframe allowances, `RustKit chrome navigation not followed`, and ipc/commands' `Navigate to` / `Activated tab` / `Updated active tab URL` / `Opening in external browser` / `Credential saved for`. Prometheus's rule: URLs in the log carry no query or fragment.

- `page_url_for_log` (app) gives the whole URL only when IPC bodies are logged whole: `HIWAVE_DEBUG=1`, or `HIWAVE_TEST_HOOKS=1`. The hooks case matters because the real-window checks read queries (h16's `?from=a2`). Otherwise it uses `url_for_log`.
- `url_for_log` (#910's helper) now also drops userinfo, and cuts a `data:` URL at its media type.
- A saved credential's URL is always stripped.
- The new real-window check found two more leaking lines outside the app: hiwave_shell `Updating tab … URL to:` and rustkit_engine `Loading URL url=`. Both now log scheme+host+path at info, with the whole URL on a debug line beside it. Each crate gets its own small `url_for_log(&Url)` with a unit test; rustkit-engine does not depend on the app or on hiwave-core.

Deviation from the row: it says "full URL only under HIWAVE_DEBUG=1". This PR also keeps the URL whole under HIWAVE_TEST_HOOKS=1, which is the switch #910 already uses for IPC bodies. Without it, h16_click_nav loses the `?from=a2` it reads.
