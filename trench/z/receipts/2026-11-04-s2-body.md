## S2: coalesce adjacent pointer moves on the content thread

PLAN-z row **S2** (Pete's hand test 11-03, reddit): "288 mousemove/pointermove/enter/leave handlers 'stopped at the script budget' with elapsed_ms=0, so they never ran".

### What the log actually shows (`live-20261103T1704.log`; tool `trench/z/tools/s2/stops.py` on the Atlas hub)
The row's premise does not hold. The 288 stops are one burst, 22:10:39.670–22:10:44.748, and it starts **after Pete asked for yahoo** (`Chrome IPC navigate` at 22:10:39.239). The engine only began `Loading URL https://www.yahoo.com/` at **22:10:44.748, 5.5 s later**. In between, the content thread worked through **11 queued pointer moves for reddit**, the page being left, each a `hover_or_focus` relayout of ~430 ms (`build_ms` ~400, `tree_reused=false`). The navigation had already set the old document's cancel word, so every listener those moves reached was cut at once: `elapsed_ms=0`, logged with the budget wording. The other burst in the log (5 stops at 22:05:53) has the same shape: a link click from walmart. No pointer listener on reddit was stopped while Pete was using the page.

So the two real defects are:
1. **A navigation waits behind every pointer move queued for the old page.** The viewhost merges moves while they wait window-side, but once handed to the busy content thread they queue one per window tick, uncoalesced.
2. Each reddit move costs ~430 ms of hover restyle (full rebuild). That's a separate cost item, not in this PR.

### Fix (this PR)
`page_protocol::coalesce`: a `MouseMove` replaces an earlier `MouseMove` when only `NoteInput` marks and `Render`s sit between them. The page hears the latest position once, which is what Chromium does: coalesced pointer events, dispatched once per frame. Nothing is reordered. A press, key, click, wheel, live turn or navigation between two moves keeps both. Every input mark is kept, so input-to-present still counts from the first move. On the log's case: 11 moves then the navigation become 1 move then the navigation, roughly 0.4 s before the load instead of 5.5 s.

**Red first:** `3c3c3dbd` `content_thread::tests::coalesce_keeps_only_the_latest_of_adjacent_moves`: `[note, move 1, note, move 2, render, note, move 3, navigate]`. On develop 76c6ff8b it fails with moves `[1, 2, 3]`, want `[3]`. The same test pins that a press between moves keeps both. **Fix `1c7da77c`: passes.**
